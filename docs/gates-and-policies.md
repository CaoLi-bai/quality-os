# 门禁与决策权

| 门禁 | 确定性检查 | 阻断条件 | 人的职责 |
|---|---|---|---|
| G0 规格 | ID、来源、风险、Oracle、验收条件、批准人 | 高风险未决、无来源 Oracle、无验收、未批准 | 解释业务规则，解决歧义 |
| G1 计划 | 需求—用例追溯、未知需求、孤立用例、覆盖缺失 | 用例无需求、需求未覆盖、Oracle 缺失 | 审查风险优先级和测试范围 |
| G2 候选 | 测试函数与断言、独立审查结果 | 无测试、无断言、审查拒绝 | 审查业务语义与剩余风险 |
| G3 执行 | Good Build 真实退出码与 JUnit | 基线失败、无报告 | 判断产品、需求或环境问题 |
| G4 故障证明 | 每类映射故障必须被对应候选抓到 | 任一故障逃逸 | 判断故障是否代表有效业务风险 |
| G5 自愈 | locator-only AST Diff、独立候选目录 | 断言、预期、Skip、删除或控制流变化 | 审查候选并执行目标／关联回归 |
| 发布 | 证据完整、人工批准、无非法漂移 | 未审批、假绿、证据缺失 | 命名负责人签字 |

## 不可变测试意图

测试意图由已批准规格定义。当前系统行为、模型置信度和“修复后能通过”都不是 Oracle 来源。

以下变化不属于自愈：

- 把 403 改成 200。
- 修改退款金额或错误码预期。
- 删除越权、资金或安全测试。
- 增加 Skip、xfail 或无依据重试。
- 修改产品代码让测试通过。
- 用更宽松断言替代原断言。

## 人工批准不是装饰

完整离线演示结束后仍显示 `pending_human_approval`。这表示技术证据已准备，而候选资产没有自动进入正式回归库。项目没有伪造审批人，也不提供一条命令跳过批准。

## 安全与隐私

所有订单均为合成数据。真实项目接入时应增加：密钥隔离、测试环境最小权限、网络白名单、数据脱敏、日志保留策略和外部工具审批。模型分类器不能替代这些确定性控制。
