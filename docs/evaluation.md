# 评测指标与证据口径

## 三层评分器

### 代码评分器

规格结构、来源追溯、未决高风险、用例孤立、测试断言、非法 AST 变化、真实退出码、故障检出和 pass^k。这些指标可重复、成本低，是硬门禁。

### 模型评分器

适合开放性风险遗漏、表达质量和覆盖建议。当前离线运行显示 `model_grader=not_run`，不能把代码检查结果冒充 LLM 评审。在线评审也要与生成者分离上下文，并保存原始输出。

### 人工评分器

负责业务歧义、风险优先级、Oracle 变化、主观 Rubric 校准和最终批准。人工结果应另存，不得由系统代签。

## 指标定义

| 指标 | 本项目口径 |
|---|---|
| Good Build 通过率 | 正确版本中通过测试数／执行测试数 |
| 故障检出率 | 被至少一条候选测试抓到的映射故障数／注入故障总数 |
| pass@k | k 次尝试中至少一次符合黄金任务预期 |
| pass^k | k 次尝试全部符合预期，适合稳定性门禁 |
| 假绿信号 | 应阻断任务被接受，或通过改断言／Skip／删除获得通过 |
| 人工接管 | 需要人解决歧义、分类 Unknown、审查高风险或批准候选的次数 |
| Provider 成本 | 实际 CLI／模型耗时与可用费用数据；fixture 不填模型费用 |
| 有效用例成本 | 总模型费用与人工成本／通过全部证据并获人工批准的用例数 |

## 当前不能声称的指标

- 没有人工历史基线，不能声称提效百分比。
- 没有真实线上缺陷，不能声称降低线上事故或逃逸率。
- 没有在线模型对照实验，不能声称某模型更优。
- 没有完整变异测试工具接入，不能把四类故障注入说成全库 mutation coverage。
- 没有命名审核人签字，不能声称候选资产已正式入库。

## 后续真实测量

选择同一批新需求，分别记录人工流程与 QualityOS 流程的准备耗时、审核耗时、返工、有效用例、无效断言和模型费用。至少多轮、多需求测量后再给区间，不用一次成功演示推导组织级 ROI。
